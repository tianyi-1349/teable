第 1 步：Kimi K2.6 生成结构地图

结构扫描 
你现在是仓库结构分析专家。请对这个代码仓库做“全目录代码结构扫描”，目标是建立一份完整、清晰、可供后续能力盘点使用的结构地图。

分析目标：
1. 识别仓库的顶层分层结构
2. 识别前端、后端、共享包、数据库、插件、v2 子系统的职责边界
3. 识别每个主要目录下已经存在的模块类型、核心入口、主要资源类型
4. 标出高价值功能域，例如：
   - auth / oauth / user / organization
   - base / table / field / record / view / dashboard
   - share / published app / base-node / automation / workflow
   - import / export / attachments / comments / notifications
   - plugin / sdk / openapi / v2 runtime / db schema
5. 为后续能力识别建立“功能入口地图”

你的工作方式：
1. 优先按目录和模块划分理解系统
2. 用文件命名、目录命名、入口文件、controller、page、route、schema、index 导出等信号推断职责
3. 关注“模块存在且有实现痕迹”的能力
4. 你的任务是做结构地图，不做最终能力结论
